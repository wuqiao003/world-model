# 2026-09-01 日报：从「借来的模型园」转向「自训练模型园」

## 0. 一句话

聚类 bootstrap 揭示我们的瓶颈从来不是系统数（已 63），而是**只有 3 个独立模型簇**；
今天打通了集群上的完整数据 + 自训练管线，把模型簇从 3 提到 20，并借此让 K3 复活。

## 1. 昨天的结论需要加一个限定词

昨天报的「大动作区可控性指标反超保真度」用的是**按系统重采样**的 bootstrap。
但系统并不独立：同一 ckpt 的 21 个动作管线共享同一个编码器，
同一管线的 3 个 ckpt 共享同一种扰动。补做聚类重采样后：

| 分层 / 效用 | Δ | 按系统 (63 簇) | 按管线 (21 簇) | 按 ckpt (3 簇) |
|-------------|---|----------------|----------------|----------------|
| q0 / `−gt_rank`（保真度胜） | −0.163 | P=1.000 | P=1.000 | **P=1.000** |
| q1 / `mppi_cos`（保真度胜） | −0.073 | P=0.999 | P=0.995 | **P=1.000** |
| q2 / `mppi_cos`（我方胜） | +0.152 | P=0.033 | P=0.053 | **P=0.285** |

**结论的强度是不对称的**：

- 「小动作区保真度指标预测规划效用更好」——三种口径全部稳固。这是一个**可以写进论文的
  否定性发现**：CAF 类指标在真机 PushT 的小动作区并不优于一步保真度。
- 「大动作区可控性指标反超」——只在最宽松口径下勉强显著。**按最保守（也最诚实）的
  ckpt 聚类口径，目前没有证据。**

这条限定词写进了 `reports/2026-08-31.md` §9.0 与 `16-main-track-roadmap.md` §7.1。

## 3. 今天打通的东西

### 3.1 集群网络能力被重新测出来了

之前认为集群拿不到 HF 权重，所以一直走「本地下载 → scp → kubectl cp」。重测发现：

| 通道 | 结果 |
|------|------|
| GitHub tarball | 200，5.5MB 正常下载 |
| HF LFS range 读 | 206，单连接 ~0.45 MB/s |
| **16 路并行分块** | **聚合 ~9 MB/s** |
| pip | 正常 |

于是完整数据集 **10.44GB 用 28 分钟直接落到集群**（`code/cluster_fetch_dataset.sh`，
64MB 分块 + 逐块尺寸校验 + 重试 + 拼接后 HDF5 验证）。
`kubectl cp` 从此只用来同步 56KB 的代码。

### 3.2 官方训练代码可复现，且损失极简

拿到 `github.com/lucas-maes/le-wm` 的 `train.py`。它依赖 `stable_pretraining` +
`stable_worldmodel` 两个外部包，而且 tarball 里**缺 hydra config 目录**——直接跑风险高。
但核心损失只有 4 行：

```
pred  = predict(emb[:, :ctx], act_emb[:, :ctx])
loss  = (pred - emb[:, n_preds:]).pow(2).mean() + λ · SIGReg(emb)
```

端到端、无 EMA、无 stop-grad（SIGReg 单独防塌缩，这正是 LeWM 的卖点）。
SIGReg 本身 25 行自包含。所以改为**用已跑通的部件自己写训练器**
（`code/train_wm.py`），只需 torch/transformers/einops/h5py。

从已发布 ckpt 反解出精确架构：

| 部件 | 配置 |
|------|------|
| 编码器 | ViT hidden 192, 12 层, 3 头, intermediate 768, patch 14, 224² → 5.5M |
| 预测器 | ARPredictor depth 6, heads 16, mlp 2048, AdaLN-zero 条件注入 → 10.8M |
| 动作编码器 | Embedder, 输入 10 维（5 tick × dx,dy）→ 192 |
| projector / pred_proj | MLP |
| ctx_len | 3 |
| 合计 | **18.0M** |

训练器把 checkpoint 存成现有 adapter 直接能加载的格式（pickled JEPA +
`jepa.py`/`module.py`/`action_scaler.json`/`meta.json`），adapter 从 `meta.json`
读各模型自己的 `history_size`，所以 `ctx1/2/5/8` 这类模型无需改评测代码。

### 3.3 模型园预注册

`code/train_zoo_spec.json` 里 17 个配置**在见到任何结果之前固定**，全部报告不筛选：

| 轴 | 配置 | 作用 |
|----|------|------|
| seed | `base_s0/s1/s2` | 同 recipe 独立重训 → ckpt 间变异的下界 |
| 容量 | `enc6`, `tiny`, `pred2` | 架构造成的质量谱 |
| 预算 | `ep_short`, `ep_vshort`, `frac10`, `frac30` | 优化造成的质量谱 |
| 正则 | `lam0`（含塌缩风险）, `lam1`, `lr_hi` | 表征质量谱 |
| **记忆** | `ctx1/2/5/8`（+`base_s0`=ctx3） | **K3 需要的训练版记忆容量扫描** |

一次解决三件事：(a) 模型簇 3 → 20；(b) 质量谱由容量/预算/正则产生，
而不是靠破坏动作通路制造——直接回应「你的模型园只有动作扰动」这一致命质疑；
(c) K3 拿到**训练出来的** Mem-Ctrl 轴，替代已被否掉的推理期干预。

### 3.4 顺手补的模型侧扰动

`k1k2_real_eval.py --weight-noise`：对预测器权重加 N(0, σ·std(W)) 噪声，
σ ∈ {0.005 … 0.2}，每个变体跑 `id/zero/neg` 三条管线。
这是**不碰动作通路**的退化方式，所以保真度与可控性可以独立变化。
已发布 3 个 ckpt 因此从 63 系统扩到 117 系统、模型簇 3 → 21。

## 4. 数据与统计口径的其他补强

## 6. 模型园训练完成（199 分钟，18/18）

质量谱确实展开了，而且顺带产生了一个对论文有用的反例：

| 模型 | best_val | latent rms | 说明 |
|------|----------|-----------|------|
| `lam0` | **0.00000** | **0.009** | λ=0，表征完全塌缩 |
| `mem3` | 0.00319 | 0.875 | |
| `tiny`(2.6M) | 0.01352 | 1.028 | |
| `base_s0` | 0.01847 | 1.033 | 参考配方 |
| `frac10` | 0.02815 | 1.055 | 只用 10% 数据 |
| `lam1` | 0.38156 | 0.943 | λ=1，过度正则 |

> **`lam0` 按绝对验证损失是「最好的模型」，但它的潜空间塌缩到 rms=0.009。**
> 预测一个近乎恒为零的量当然误差极小。这是「绝对潜空间预测误差不能跨模型比较」的
> 活证据，也是本文所有指标都相对于尺度匹配基线归一化的直接理由。
> 论文里可以直接用这一行做 motivation。

自训练模型与已发布 ckpt 的对比（留出集，尺度无关指标）：

| | 自训练 | 已发布 v2（模型卡） |
|---|---|---|
| `pred_id_ratio` | 0.018–0.022 | 0.465 |
| `gt_rank_pct`（越低越好） | 0.055–0.180 | 0.33–0.44 |

模型园「好的那一端」确实好，不是稻草人。
